# AI 动作翻译器 · 详情

给计算机初学者和学生的 DSH 学习辅助层：**边解释 AI 的动作，边教你 Agent 是怎么跑起来的。**

## 解决什么问题

初学者面对 AI 操作电脑时，最常见的一句是：

> 它到底在干什么？为什么这么做？这串报错是什么意思？

这个插件不改变 AI 做的事，只在它动手前后加一层**人话解释**，并把每个动作放回项目结构里，告诉你它现在在哪一层。

第二句同样常见的是：

> 它已经开始跑了，我现在还能改主意吗？

所以它还要让每一步都**看得见可以打断的位置**——这是插件和「事后看日志」最大的区别。

## 它做什么

| 能力 | 说明 |
|---|---|
| 动作翻译 | 工具调用前说清「要做什么、为什么、影响」，返回后说清「实际发生了什么、对下一步意味着什么」 |
| **一步一步解析** | `stepParse`（默认开）：把动作拆成编号小步，每步点明用了什么工具、碰了哪个文件、处在项目哪一层 |
| 分级讲解 | `knowledgeLevel` 四档：`plain` 全白话 / `guided` 边做边学 / `balanced` 白话+术语+机制 / `deep` 追调用链 |
| 项目地图 | 固定六层定位：入口/启动点 → 配置与依赖 → 核心模块 → 工具/服务边界 → 输出/界面 → 测试与验证 |
| 阶段小结 | 完成可验证小阶段后，用 2～4 句承接「完成了什么 / 在地图哪层 / 仍未知 / 下一步」 |
| **中途介入窗口** | 每完成一个可验证小步，标出「现在可以打断我」与此刻改主意的最小代价；用户换目标时先复述放弃的旧目标 |
| 人物语气 | `persona` 可自定义（≤600 字）；只影响表达，不影响事实与安全边界 |
| **动作时间线** | `timeline`（默认开）：把这一路的工具调用按时间排成只读列表，带分类、耗时、成功/失败标记。它**只在面板里回看，不写进提示词**，所以看历史不占上下文 |
| **术语卡片** | `glossary`（默认开）：`waterfall`、`peerDependency`、`HMR`、`EPERM` 这类词第一次出现时就地给一句话；表里没有的词，要求按可观察行为现讲，不许编定义 |
| **失败案例库** | `failureBook`（默认开）：报错按层归档（鉴权/权限/路径/依赖/网络/服务/语法/测试），同一类只记一条并累计次数，存在 `~/.dsh/ai-action-translator/failures.json` |
| 配置预设 | 三档一键切换，不用逐个手调 20 个字段 |
| 配置导出/导入 | 存成 JSON，换电脑或分享给别人 |
| 运行统计 | 看见「观察了多少次工具调用」，确认它真的在工作 |
| **事前守门** | `guardMode`：动作执行前检查高风险形状（递归删 / 关机 / 改权限 / 读凭据 / 破坏性 git / 写系统目录 / 装依赖 / 停服务 / 外连）。`warn` 只提醒，`deny` 真拦。只读参数、不改参数，`off` 时连监听都不注册 |
| **多 Agent 名册** | 时间线每条标出「是谁做的」；面板显示参与数、在跑几个。系统级调用如实留空，不猜成「主 agent」 |
| **侧栏常驻面板** | 右侧栏「动作回看」页签：时间线、失败案例、术语卡片一眼可见。只读回看，不写进提示词 |
| **学习练习册** | `drill`：攒够 `drillEvery` 条真实动作自动出一道复述练习，只引用真跑过的动作，同一批只出一次 |
| **本轮装配说明** | 开关是运行时的、静态提示词段改不了；于是每轮现算一段「本轮生效什么、关掉了什么」，避免模型照着旧文字讲已关掉的事 |

## 它不做什么

这些是**设计上刻意排除**的，不是还没做：

- 不注册任何工具，不接管工具执行
- 不拦截、不否决、不改写任何工具结果（只用 `tools/result` 这个纯广播事件做只读观察）
- 不联网、不外发任何内容
- 不读写你的项目文件
- 不自动执行动作
- 不声称知道模型的隐藏推理 —— 只解释可观察的事实
- **不替你做决定**：它只把「现在可以改方向」和「改方向的代价」摆出来，决定权始终在你手上

## 怎么用

**主入口：DSH 设置页里的「AI 动作翻译器」分区。**

改完保存，下一轮对话自动生效，不用重启 DSH。

分区里还有一个「打开完整页面」按钮，可以打开服务端渲染的完整面板。

> ⚠️ 不要手敲 `/api/ai-action-translator/` 这个地址。`dsh web` 内核把 `/api*` 锁在「启动令牌 → 签名 Cookie」之后，直接访问会先被内核拦下返回 `401 dsh web authentication required`，请求根本到不了插件。这是内核的票据保护，不是插件缺陷。

## 适配范围

**只适用于 DeepSeek Harness（DSH）。** 依赖 DSH 独有 API：`systemPrompt.section()`、`settings.section` 槽位、`~/.dsh/` 数据目录。不能用于其他 Agent 工具。

支持的 DSH 版本写在 `package.json` 的 `dsh.engines.dsh`（当前 `>=0.2.2-rc.3`）。在更低版本上没有验证过，不承诺行为一致。

## 安全边界

- 面板仅应答本机回环（Host 限 `127.0.0.1` / `[::1]` / `localhost`，Origin/Referer 须同源）
- 请求体上限 64KB；未知字段与坏 JSON 返回 400
- 密钥形状字段名主动拦截
- `enabled` / `order` 属结构配置，面板无法修改
- 零网络代码，零运行时依赖

## 验证

```bash
npm ci
npm run verify    # 语法 + 测试 + 隐私扫描
node scripts/load-smoke.mjs   # 假宿主装载冒烟（可选，单独跑）
```

七组测试共 132 项：插件契约 / 服务端模块与文档回归 / 浏览器半身 / 动作回看层（分类器、失败分层、时间线、失败案例库、术语表、`/activity` 路由）/ 事前守门（10 条规则、三种模式、放行通道、静音例外）/ 多 Agent 名册 / 学习练习册。装载冒烟用假宿主把 `apply()` 完整跑一遍——它会真的走一遍守门放行、名册登记、练习册出卡与两端提示词段，**但不等于**已经装进真实 DSH（那需要重启桌面版）。
