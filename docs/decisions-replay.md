# 决策回放器 · 设计草案（0.9 目标，尚未实现）

> 状态：**设计文档 / 未实现**。本文件只描述最小可验证版本，不改代码。
> 现有 0.8.x 的全部能力保持不变；0.9 只增加「决策层」，不增加新的解释动作。

## 1 · 一句话

现在它解释**每一步**；0.9 要让它在关键时刻留住**四个问题的答案**：

> 改了什么 · 为什么选这个方案 · 被否掉的方案是什么 · 失败根因是什么

区别在于**粒度**：解释是逐动作的、会过去；决策是要能在一个月后回看的、必须留痕。

## 2 · 为什么不是「更多解释」

0.8 的问题是它太勤快：每一步都给你一段旁路说明。对初学者有用，对**已经在用 Agent 干活的人**是噪音——他们要的不是「这步在做什么」，而是「刚才那个岔路口，你为什么走左边」。

所以 0.9 的取舍是：

| | 0.8 解释层 | 0.9 决策层 |
|---|---|---|
| 触发 | 每个工具调用 | 只在出现分支/失败/不可逆动作时 |
| 载体 | 侧栏正文 + 提示词注入 | 侧栏「决策」页 + 落盘 JSONL |
| 寿命 | 本轮会话 | 跨会话可回看 |
| 默认 | `explainMode: open` | `decisionReplay: off`（默认关） |

## 3 · 三个使用场景

**场景 A · 一小时后回来接手**
你让 Agent 重构了一个模块，去开会回来发现它把三个函数合成一个。打开「决策」页，第一条就是：`合并 parseUser / parseAuth → parseIdentity（理由：两处字段重复 87%）`，第二条是 `否掉：保留两函数只抽公共部分（理由：调用点仅 3 处，抽象成本高于收益）`。你不用重读 diff 就能判断要不要接受。

**场景 B · 出事了要归因**
线上报错，你要确认「这个 fallback 是谁加的」。决策页按文件过滤，显示 `kind: failure` 那条：`测试 test_upload 连挂两次 → 根因：临时目录在沙箱外 → 处理：改写到 workspace/.tmp`。根因不是结果，是**当时判定的原因**。

**场景 C · 不可逆动作前的确认**
`git push` / `rm -rf` / `npm publish` / 覆盖 `.env` 这类动作被单独标 `irreversible`，即使在别的会话里也能查到「上一次是谁批准的、批准时说的是什么」。

## 4 · 最小可行版本（0.9.0）

### 4.1 只记四类决策点

| kind | 何时记 | 必填字段 |
|---|---|---|
| `choice` | 同一目标下出现 ≥2 个候选动作（读两个文件选一个改、两种修法选一种） | `question` `chosen` `rejected[]` |
| `rejected` | 明确否掉一条路，并给出否掉的理由 | `rejected[]` `whyRejected` |
| `failure` | 同一目标连续失败 ≥2 次，之后成功或改道 | `rootCause` `attempts[]` |
| `irreversible` | 命中不可逆动作清单（`rm`/`del`/`git push`/`npm publish`/覆盖 `.env` 等） | `target` `approvedBy` |

**不记**：单次成功的普通读写、lint 自动修复、格式调整、只读探查。宁可漏，不可噪。

### 4.2 数据结构（一条一行的 JSONL）

```json
{"v":1,"id":"d_20261121_1","t":1763700000000,
 "kind":"choice",
 "goal":"让 test_upload 通过",
 "question":"临时目录不可写，怎么绕过",
 "chosen":"改用 workspace/.tmp 作为 TMPDIR",
 "rejected":[{"option":"给 C:\\Users\\...\\Temp 加可写根","why":"越权范围过大，且换机器就失效"}],
 "evidence":["tool:bash#12","err:Errno 13"],
 "files":["tests/test_upload.py"],
 "outcome":"pass",
 "session":"<sessionId>","agent":"lead"}
```

- 落盘位置沿用现有 store 目录（`.dsh/` 下），**不新增服务**；
- 单文件环形上限 500 条 / 512KB（与现有时间线同一套裁剪阈值机制，阈值按行宽推导，不写死行数）；
- `v` 字段留给未来迁移，读到不认识的就跳过而不是报错。

### 4.3 怎么采（零额外工具调用）

不新开工具、不额外问模型。从**已有时间线事件流**的差分里派生：

1. 时间线里已有每次工具调用的 `{tool, args摘要, ok, 耗时}`；
2. 决策判定是纯本地规则：同一 `goal` 下出现两条不同 `target` 的写操作 → 候选 `choice`；
3. 同一 `target` 连续 `ok:false ≥2` → 候选 `failure`（根因取最后一次报错的首行分类）；
4. 命中不可逆清单 → 无条件 `irreversible`。

**风险点**：规则派生的「选择」可能是假的（例如先读 A 再读 B 不是"选择"）。所以派生结果先进 `pending` 队列，只在**用户打开决策页**时才落盘（`decisionReplay: review` 模式），或直接落盘但标 `auto:true` 供过滤（`decisionReplay: auto` 模式）。

### 4.4 怎么展示

侧栏新增第三个 tab「决策」（现有：解释 / 时间线）：

```
[决策]  本轮 2 条 · 未确认 1 条
──────────────────────────────
● 11:32  choice    合并两个解析函数      ▸ 展开
        选了：parseIdentity（字段重复 87%）
        否掉：只抽公共部分（调用点仅 3 处）
○ 11:18  failure   临时目录不可写        ▸ 展开
        根因：沙箱外路径；处理：改到 .tmp
```

- 一行一句摘要，点开才显示 `rejected[]` 与 `evidence`；
- 顶部四个过滤：全部 / 只看 choice / 只看 failure / 只看不可逆；
- 时间倒序，跨会话按 `session` 折叠；
- 「未确认」= `auto:true` 且用户没点过「这条对」。用户点「不对」→ 删除该条并把这条规则加入本项目的本地抑制表。

### 4.5 与现有 `systemPrompt` API 的兼容

| 关注点 | 做法 |
|---|---|
| `systemPrompt.section()` | **不使用**。它是规则/人格段，决策记录是数据，塞进去会污染人格并持续占上下文 |
| `systemPrompt.context()` | 只用它注入**一段**最近决策摘要，且仅在 `replayBrief: on` 时；长度上限 800 字符，超出按时间截断 |
| 默认行为 | `replayBrief: off` → 提示词零变化，纯粹是侧栏功能 |
| 旧配置 | 新增字段全部有默认值；旧 profile 不改 JSON 也能启动（与 0.8 的配置归一化同一路径） |
| 版本要求 | 不新增 DSH 依赖，仍是 `>=0.2.2-rc.3` |

### 4.6 风险与缓解

| 风险 | 缓解 |
|---|---|
| 误判「决策」，噪音比 0.8 还大 | 四类白名单 + 事后「这条不对」的本地抑制表；默认 `decisionReplay: off` |
| 上下文膨胀 | 默认不注入提示词；注入只给 800 字符摘要，不给完整记录 |
| 隐私（本机路径、命令、报错原文落盘） | 落盘前过一遍路径脱敏（家目录 → `~`）；`evidence` 只存引用 id 不存正文；提供「清空决策记录」 |
| 与「教初学者」定位打架 | 定位改为双层：默认仍是解释层；决策层是给「已经在用 Agent 干活」的人的第二档 |
| 会话 id 不稳定 | 用现有 session 标识 + 时间戳做复合主键，读不到就退化成本地时间 |

## 5 · 不做的事

- 不做「自动总结整场会话」（那是 LLM 调用，成本与不确定性都高）；
- 不做跨机器同步 / 云端存储；
- 不修改 Agent 的实际决策逻辑 —— 它是**记录器**，不是**控制器**；
- 不在 0.9 里做可视化 diff 回放（先证明记录本身有用）。

## 6 · 验收标准（0.9 可判定）

- [ ] 一次包含「两种修法选一种 + 一次失败重试 + 一次 git push」的真实任务里，决策页出现 **3 条**，且没有一条是普通读写
- [ ] 关掉 `decisionReplay` 后，提示词与 0.8 逐字节一致（可用现有 smoke 断言）
- [ ] 打开 `replayBrief` 后，注入内容 ≤ 800 字符，且 `systemPrompt.section()` 段未变
- [ ] 500 条记录时侧栏打开 < 200ms
- [ ] 落盘的 JSONL 里 `grep -c "C:\\\\Users"` = 0（路径已脱敏）
