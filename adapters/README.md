# 多宿主适配层

> GENERATED by tools/build-adapters.mjs — 不要手改，改 adapters/_core 或 lib/ 后重新生成。

把同一套「动作翻译 + 事前守门」的判断规则，做成几个宿主各自能读的形态。

## 先看这张表

| 目录 | 宿主 | 动作前拦截 | 提示词写到 |
|---|---|---|---|
| [`claude-code/`](claude-code/README.md) | Claude Code | ✅ 可阻断 | `CLAUDE.md` |
| [`codebuddy/`](codebuddy/README.md) | CodeBuddy / WorkBuddy | ✅ 可阻断 | `AGENTS.md` |
| [`qwen-code/`](qwen-code/README.md) | Qwen Code（千问） | ✅ 可阻断 | `QWEN.md` |
| [`codex/`](codex/README.md) | Codex | ❌ 没有可挂的钩子 | `AGENTS.md` |

**「动作前拦截」这一列是唯一值得你仔细看的地方**：能拦的宿主，钩子脚本会在命令真正执行
之前就返回 deny；不能拦的宿主，这里只有提示词，模型可以不理它。我不为了表格好看而假装它们一样。

## 两边的关系

```
lib/guard.js                 ← 规则的唯一出处（DSH 插件与这里共用同一份）
   ↓ tools/build-policy.mjs
adapters/_core/policy.json   ← 生成出来的快照
   ↓ tools/build-adapters.mjs
adapters/<宿主>/...          ← 每家一份薄壳：配置 + 钩子脚本 + 提示词
```

`_core/` 是**宿主无关**的：判定器（`judge.mjs`）、提示词段（`prompt.mjs`）、时间线（`timeline.mjs`）、
钩子运行时（`hook.mjs`）都在这里，里面不出现任何宿主名字——有测试盯着这件事。
每个宿主目录只负责三件小事：配置写在哪、钩子长什么样、提示词叫什么名字。

## 为什么是生成出来的，而不是手写

手抄的规则一定会漂。改了 `lib/guard.js` 里某条正则却忘了改 adapter 那份，两处就开始说不同的话
—— 而这种不一致在测试里是绿的、在用户那儿是真放行。所以这里的东西全部由脚本生成：

```bash
npm run build:policy     # lib/guard.js  → adapters/_core/policy.json
npm run build:adapters   # policy + 提示词 → 每个宿主目录
npm run check:adapters   # 只校验不写盘；有漂移就退出 1
```

## 装之前请先读这一句

这些适配层**不会**替你改用户级配置（`~/.claude/`、`~/.codex/` 之类）。它们只生成项目级文件，
你自己决定复制到哪个项目里。装完先喂一条 `rm -rf <某个临时目录>` 试试 —— 
**没试过就当它没生效**，别凭「我装了」这三个字放心。
